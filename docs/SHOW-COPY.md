# نسخة العرض (بلا بيانات تجريبية)

تشغّل الموقع بقاعدة بيانات فارغة وحساب مسؤول واحد، وبدون حسابات أو طلبات تجريبية.

## التشغيل

```bash
npm ci
npm run build
DATA_DIR=./show-data \
ADMIN_EMAIL=admin@your-domain.example \
ADMIN_PASSWORD='كلمة-مرور-من-12-حرفًا-على-الأقل' \
REGISTRATION_OPEN=true \
COOKIE_SECURE=false \
npm start
```

- `DATA_DIR` مجلد جديد فارغ. لو فيه بيانات تجريبية قديمة يرفض الخادم التشغيل عمدًا.
- `ADMIN_EMAIL` و`ADMIN_PASSWORD` يُنشئان المسؤول الرئيسي مرة واحدة عند أول تشغيل فقط.
- `REGISTRATION_OPEN=true` يفتح تسجيل الطلاب. بدونه تظهر صفحة «إنشاء الحسابات غير متاح حاليًا» ولا يمكن لأي طالب فتح حساب.
- `COOKIE_SECURE=false` للتجربة على `http` فقط. على استضافة `https` احذفه (الكوكي Secure افتراضيًا في الإنتاج).
- خلف وسيط عكسي أو منصة استضافة أضف `TRUST_PROXY=1`. التفاصيل الأمنية في [SECURITY.md](SECURITY.md).
- لا تضع كلمات المرور في المستودع؛ مكانها متغيرات بيئة الاستضافة.

## ما يتغير في الوضع الحقيقي

- لا يظهر زر «تعبئة بيانات الحساب التجريبي» ولا يوجد `/api/demo-accounts`.
- لا توجد طلبات ولا طلاب، فتظهر الشاشات بحالاتها الفارغة.
- الاستمارة لا تحمل أي عبارة تجريبية.
- البريد الإلكتروني مغلق حتى يُضبط SMTP (انظر [EMAIL.md](EMAIL.md)).

## قبل العرض

1. غيّر `office` في `config/faculty.json` إلى مكتب التسليم الفعلي (القيمة الحالية «سيُحدد مكتب التسليم قبل التشغيل الرسمي»).
2. أنشئ حساب موظف من «إدارة الموظفين».
3. سجّل طالبًا من صفحة التسجيل وجرّب الدورة كاملة: تقديم، استمارة، اعتماد.
4. اختبار يغطي هذه الدورة على قاعدة فارغة: `npm run test:real`.
