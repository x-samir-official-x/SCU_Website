# معاينة Vercel والتحديث التلقائي

## حدود المعاينة

Vercel ينشر نسخة عرض تفاعلية ثابتة، تُبنى بالأمر `npm run build:preview` وتخرج إلى `dist-preview/`. لا يُشغّل Express أو SQLite أو Chromium على Vercel في هذا الوضع.

تستخدم المعاينة Service Worker وIndexedDB داخل المتصفح لتجربة الحسابات والطلبات والمرفقات والمراجعة. البيانات تبقى بعد تحديث الصفحة في نفس المتصفح، لكنها **ليست مشتركة بين الأجهزة أو ملفات المتصفح المختلفة**. الحسابات والصلاحيات فيها محاكاة للعرض، وليست حماية لبيانات حقيقية. لا تستخدم بيانات أو كلمات مرور شخصية حقيقية.

لتجربة دورة العمل، قدم النشاط بحساب الطالب، ثم اخرج وسجل كموظف في **نفس المتصفح** للمراجعة، ثم عد لحساب الطالب لمشاهدة النتيجة. يمكن للمسؤول الرئيسي إعادة فتح الطلب أو سحب اعتماده لمتابعة التجربة.

الاستمارة تفتح في صفحة طباعة تحتوي البيانات الفعلية للطلب. اختر «طباعة الاستمارة / حفظ PDF»، ثم «حفظ بتنسيق PDF» من نافذة المتصفح. النسخة ذات الخادم تظل تولد PDF مباشرة باستخدام Chromium كما كانت.

## إعدادات مشروع Vercel

الإعدادات محفوظة في `vercel.json`:

- Framework: Vite.
- Install: `npm ci`.
- Build: `npm run build:preview`.
- Output: `dist-preview`.
- Node.js: 24.x.
- Git repository: `x-samir-official-x/SCU_Website`.
- Working branch: `feat/commerce-activity-portal`.

بعد ربط المشروع بالمستودع، كل push إلى الفرع يشغّل بناء ونشر Preview جديدين. رابط الفرع الذي يعيّنه Vercel ثابت ويتحدث بعد نجاح البناء. حفظ الملف محليًا وحده لا ينشر التغيير؛ يلزم commit وpush، وقد يستغرق البناء دقائق.

لا تُضف مفاتيح Google أو بيانات الجامعة إلى متغيرات `VITE_*`؛ هذه المتغيرات تُضمّن في حزمة المتصفح.

## التشغيل والاختبار المحلي

```bash
npm run build:preview
npm run test:preview
npm run preview:static
```

اختبار المعاينة يقدم ملفات ثابتة فقط، ويختبر بدء Service Worker، والتقديم ورفع الملف، وطباعة الاستمارة، وتبديل الحسابات والمراجعة واحتساب ٤٠ درجة، واستمرار البيانات بعد التحديث، وعزل جلسات المتصفحات المختلفة.

لنسخة الخادم الأصلية:

```bash
npm run build
npm run start:demo
```

تظل SQLite والمرفقات في `.data/` لهذه النسخة فقط. لا يُرفع المجلد إلى Vercel أو GitHub.

## قبل توفير تجربة مشتركة أو تشغيل فعلي

يلزم ربط قاعدة بيانات وتخزين مرفقات دائمين، وتشغيل واجهات API موثقة وتحقق هوية فعلي. نقل SQLite إلى `/tmp` في وظيفة Vercel لا يحقق تخزينًا دائمًا أو مشاركة موثوقة، ولذلك لم يُستخدم كحل للنشر.

إزالة المعاينة من نفس النطاق لصالح الخادم تتطلب إلغاء Service Worker؛ التطبيق يلغي تسجيل عامل المعاينة الخاص به عند تشغيل build عادي. لا تُستخدم أي بيانات محلية من المعاينة كمصدر ثقة للخادم.
