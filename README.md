# «أَثَر» | بوابة النشاط الطلابي — كلية التجارة | جامعة قناة السويس

نسخة تطوير وتجربة مستقلة لكلية التجارة: تقديم نشاط واحد، ومراجعته، وإصدار استمارة PDF عربية، واحتساب ٤٠ درجة بعد اعتماد الموظف.

**هذه نسخة تجريبية ببيانات وهمية، وليست نظامًا معتمدًا للاستخدام مع الطلاب الحقيقيين.** لم يُفعَّل ربط الجامعة أو تسجيل Google أو التحقق المؤسسي. المساعد المحلي وقراءة الشهادات يعملان بقواعد وأدوات داخل المتصفح والخادم نفسيهما دون أي خدمة ذكاء اصطناعي خارجية (انظر «الوظائف المتاحة»). لا ترفع مستندات شخصية حقيقية في وضع التجربة.

## معاينة Vercel

إعدادات النشر والتحديث من GitHub موجودة في `vercel.json`. نسخة Vercel معاينة تفاعلية ببيانات محلية داخل المتصفح، وليست قاعدة بيانات مشتركة بين الأجهزة. النسخة ذات الخادم ما زالت متاحة للتطوير المحلي. راجع [دليل Vercel وحدود المعاينة](docs/VERCEL.md).

الواجهة العامة على `/`، والدخول على `/login`، وإنشاء الحساب على `/register` (برقم جامعي أو قومي وموافقة على الشروط)، ولوحة الحساب على `/dashboard`. تعرض الواجهة نماذج أنشطة توضيحية قابلة للتصفية، ومسار الاستمارة والاعتماد، والأسئلة الشائعة. المعرض العام يعرض صور الأنشطة التي وافق أصحابها على نشرها فقط، مع «عرض المزيد»؛ تفاصيل النماذج بعد الدخول عبر `/community`، وبيانات الطلبات الخاصة لا تُنشر.

## التشغيل السريع

المتطلبات: Node.js 24 أو أحدث، وnpm، وChrome أو Chromium أو Edge لتوليد الاستمارة. اختياري: `pdftoppm` (poppler-utils) لقراءة شهادات PDF؛ بدونه تُقرأ الصور فقط. الخطوط العربية محلية ولا يتطلب تشغيل الواجهة اتصالًا بخدمات خطوط خارجية.

```bash
cd /workspace/SCU_Website
npm ci --cache /tmp/scu-npm-cache
npm run dev:demo
```

واجهة التطوير على المنفذ `5173`، والخادم على `3001`. يمر الوصول إلى `/api` عبر وكيل Vite. لا تُنشئ worktree؛ استخدم نسخة المشروع الموجودة داخل بيئة المهمة المعزولة.

تعرض شاشة الدخول خيارات تعبئة بيانات الحسابات التجريبية:

| الحساب          | البريد                 | كلمة المرور | الصلاحية                 |
| --------------- | ---------------------- | ----------- | ------------------------ |
| الطالب          | `student@demo.local`   | `Demo2026!` | تقديم نشاطه ومتابعته     |
| الموظف          | `moderator@demo.local` | `Demo2026!` | مراجعة الطلبات والاعتماد |
| المسؤول الرئيسي | `admin@demo.local`     | `Demo2026!` | المراجعة وإدارة الموظفين |

هذه كلمات مرور معلنة لحسابات تجريبية فقط. لا يمكن إعادة استخدام قاعدة البيانات التجريبية عند إلغاء `DEMO_MODE`؛ استخدم مجلد بيانات جديدًا تمامًا عند تجهيز بيئة غير تجريبية.

## تشغيل النسخة المبنية

```bash
npm run build
npm run start:demo
```

يقدم الخادم التطبيق والـAPI من المنفذ `3001` في هذه الحالة. `COOKIE_SECURE=false` مناسب للتجربة المحلية عبر HTTP فقط، وليس للنشر الحقيقي. للتحقق داخليًا:

```bash
curl --fail http://127.0.0.1:3001/api/health
```

## الوظائف المتاحة

- حساب الطالب وبياناته المرتبطة به، ومسودة واحدة لكل طالب في الفترة المحددة.
- تسجيل اسم النشاط ونوعه وجهته وتاريخه ووصف المشاركة.
- رفع حتى ٥ مستندات: PDF وPNG وJPEG، بحد أقصى ٨ ميجابايت للملف، مع فحص توقيع الملف وصلاحية الوصول.
- تقديم الطلب وإيقاف تعديله أثناء المراجعة؛ التعديل يُعاد تفعيله عند طلب الاستكمال.
- إنشاء PDF عربي قابل للطباعة من لقطة محفوظة عند التقديم؛ تُحفظ إصدارات الاستمارة عند إعادة التقديم.
- البحث بالاسم أو الرقم الجامعي أو الرقم القومي أو اسم النشاط، والتصفية بالحالة وترقيم الصفحات. لا تظهر أرقام قومية في نتائج البحث.
- الاعتماد بعد تأكيد استلام الاستمارة الورقية ومطابقتها؛ إعادة للاستكمال، وعدم اعتماد، وإلغاء.
- احتساب ٤٠ درجة فقط عندما تكون الحالة `approved`، دون درجات جزئية أو إضافة متكررة.
- سحب الاعتماد وإعادة فتح الطلبات بواسطة المسؤول الرئيسي فقط، مع تسجيل السبب.
- إضافة موظفين بصلاحية مراجعة، وتعطيل حساباتهم وإنهاء جلساتهم.
- سجل مراجعات، وصلاحيات على الخادم، وجلسات عبر cookies من نوع HttpOnly، وحماية CSRF، وتحديد محاولات تسجيل الدخول.
- **إنشاء الحساب:** يشترط رقمًا جامعيًا (على الكارنيه) أو رقمًا قوميًا، ويكفي أحدهما، مع موافقة على شروط الاستخدام تُسجَّل نسختها ووقتها (`src/terms.ts`، نص مسودة يحتاج مراجعة إدارة الكلية). التسجيل العام في النسخة ذات الخادم مغلق حتى `REGISTRATION_OPEN=true`، ومفتوح دائمًا في المعاينة.
- **المساعد المحلي لتعبئة الاستمارة:** يكتب الطالب نشاطه بكلماته فيقترح العنوان والنوع والجهة والتاريخ ويطبّقها بموافقته، ثم ينقله لأول حقل ناقص. قواعد نصية داخل المتصفح (`src/assistant.ts`)، لا يخترع بيانات ولا يقبل تاريخًا مستقبليًا، ولا يرسل النص لأي جهة.
- **بطاقة «مهمتك» وملفي الشخصي:** بعد إنشاء الحساب تظهر للطالب تعليمات تسجيل نشاطه خطوة بخطوة وتتحدث مع تقدمه، وصفحة `/profile` فيها بيانات الحساب وتعديل الفرقة وإضافة الرقم الجامعي وتغيير كلمة المرور وسجل المشاركات، والصورة الشخصية الاختيارية، ورقم الموبايل، وتغيير البريد، وجرس إشعارات داخل الموقع للطالب والموظف، وتأكيد البريد وإشعارات بالبريد الإلكتروني (اختيارية، تعمل مع أي SMTP، وتفاصيلها في [docs/EMAIL.md](docs/EMAIL.md)). التفاصيل في [docs/STUDENT_PROFILE.md](docs/STUDENT_PROFILE.md).
- **المعرض العام (اختياري):** لا يُنشر شيء دون موافقة الطالب وصورة مخصصة للمعرض. الاسم مخفي افتراضيًا، والاسم الأول فقط إن وافق. تُحذف بيانات الصور الوصفية (EXIF وغيرها) من الخادم. النشر فور الإرسال دون انتظار الاعتماد ولا يمنح درجة، ويمكن اشتراط الاعتماد بتغيير `gallery.requireApproval` في `config/faculty.json`. للطالب سحب موافقته، وللموظف إخفاء أي منشور. التفاصيل في [docs/GALLERY.md](docs/GALLERY.md).
- **قراءة الشهادات (مساعدة للموظف):** زر «اقرأ المستند» في صفحة المراجعة يقرأ الشهادة (عربي/إنجليزي) على الخادم ويقارن الاسم والتاريخ والجهة واسم النشاط بالطلب. لا يعتمد ولا يرفض ولا يخزّن النص، والدقة تقريبية. التفاصيل في [docs/CERTIFICATE_READER.md](docs/CERTIFICATE_READER.md).
- واجهات عربية من اليمين إلى اليسار، مناسبة للكمبيوتر والموبايل، مع حالات تحميل وأخطاء ونتائج فارغة.

## الاختبارات

```bash
npm test
npm run build
npm run test:browser
npm run test:gallery
npm run build:preview && npm run test:preview
```

`npm test` يختبر دورة العمل والصلاحيات والخصوصية والاستمارة وإلغاء الجلسات باستخدام قاعدة بيانات مؤقتة منفصلة، ويشمل المعرض والحسابات والمساعد المحلي وقراءة الشهادات. `test:gallery` يجرب المعرض في المتصفح، و`test:preview` يجرب نسخة المعاينة الثابتة. اختبار المتصفح يحتاج بناء الواجهة أولًا وChromium؛ يشغّل نسخة مستقلة ببيانات مؤقتة، ويجرب التقديم والاستكمال والاعتماد وتنزيل PDF وإدارة الموظفين والموبايل.

تُكتب نتائج المتصفح ولقطات الشاشة في مجلد جديد داخل `test-results/` لكل تشغيل، وهو مستبعد من Git. لا تُستخدم بيانات `.data/` في الاختبارات.

## بنية المشروع

```text
config/faculty.json   اسم المنصة وهوية الكلية والفترة ومكتب التسليم وإعدادات المعرض
src/                 واجهات React وTypeScript
server/              Express وSQLite والجلسات وتوليد PDF والمعرض وقراءة الشهادات
tests/               اختبارات الخادم والمتصفح
public/fonts/        الخطوط العربية وترخيصها
.data/               قاعدة البيانات والمرفقات والاستمارات؛ غير مرفوعة إلى Git
```

تُحفظ البيانات فعليًا في SQLite، والمرفقات في مجلد خاص خارج ملفات الواجهة العامة. لا يوجد اعتماد على التخزين المحلي للمتصفح لحفظ الطلبات.

## الإعدادات

تُمرر المتغيرات إلى العملية؛ ملف `.env.example` توثيقي، ولا يُقرأ ملف `.env` تلقائيًا بواسطة الخادم.

| المتغير                                                                        | الاستخدام                                                                                                              |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `DEMO_MODE`                                                                    | `true` لإنشاء حسابات وبيانات تجريبية في مجلد فارغ                                                                      |
| `DATA_DIR`                                                                     | مجلد قاعدة البيانات والمرفقات والاستمارات؛ الافتراضي `.data/`                                                          |
| `REGISTRATION_OPEN`                                                            | `true` لفتح `/api/register` للتسجيل الذاتي؛ مغلق افتراضيًا حتى يُعتمد التحقق من القيد الجامعي                          |
| `PORT`                                                                         | منفذ الخادم؛ الافتراضي `3001`                                                                                          |
| `CHROMIUM_PATH`                                                                | مسار متصفح اختياري؛ يُكتشف Chrome/Chromium/Edge تلقائيًا بحسب نظام التشغيل                                             |
| `APP_ORIGIN`                                                                   | أصل الموقع الرسمي عند اختلافه عن عنوان الخادم خلف الوكيل                                                               |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | إعدادات إرسال البريد (اختيارية؛ مغلق ما لم يُضبط `SMTP_HOST` و`MAIL_FROM`). التفاصيل في [docs/EMAIL.md](docs/EMAIL.md) |
| `COOKIE_SECURE`                                                                | `true` لإرسال جلسات الدخول عبر HTTPS فقط                                                                               |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`                                                | تهيئة أول مسؤول في قاعدة غير تجريبية فارغة؛ ١٢ حرفًا على الأقل لكلمة المرور، وتُمرر عبر إعدادات آمنة                   |

عدم تفعيل الوضع التجريبي لا يفعّل Google أو ربط الجامعة تلقائيًا. التسجيل الذاتي مغلق في النسخة ذات الخادم ما لم يُضبط `REGISTRATION_OPEN=true`، وبيانات يكتبها الطالب لا تثبت صفته؛ يلزم تنفيذ التكامل المعتمد أو استيراد سجلات الطلاب وآلية تحقق قبل استخدام بيانات حقيقية.

## قبل التشغيل الرسمي

تحتاج الجهة المختصة إلى تحديد نموذج الاستمارة، وقواعد الأنشطة والمستندات، والفترة الدراسية، ومكتب التسليم، والهوية الرسمية، والموظفين، وطريقة توثيق الطلاب. كما يلزم ربط الجامعة وتحديد الاستضافة وHTTPS وسياسة البيانات، واسترداد الحسابات، وتشغيل نسخ احتياطية مجدولة واختبار استعادتها، واختبارات حمل وأمان مناسبة للحجم الفعلي.

لا توجد مزامنة مع خادم الجامعة ولا نسخ احتياطية مجدولة في هذه النسخة، ولم تُجرَّب قراءة الشهادات على صور حقيقية من هواتف الطلاب بعد. نص شروط الاستخدام مسودة تحتاج اعتماد إدارة الكلية. البيانات والمؤشرات المعروضة في وضع التجربة مشتقة من السجلات التجريبية، ولا تمثل أعدادًا رسمية.

للتخصيص لكل كلية، ابدأ بنسخة المشروع المستقرة، وعدّل `config/faculty.json` والهوية البصرية، واستخدم مجلد بيانات وإعدادات مستقلة. الربط المركزي لاحقًا يحتاج واجهة معتمدة وعزل الصلاحيات ومعالجة انقطاع الاتصال؛ نسخ الفولدر وحده لا ينفذه.
