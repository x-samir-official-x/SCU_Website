# أثر — بوابة النشاط الطلابي لكلية التجارة

نسخة تطوير وتجربة مستقلة لكلية التجارة: تقديم نشاط واحد، ومراجعته، وإصدار استمارة PDF عربية، واحتساب ٤٠ درجة بعد اعتماد الموظف.

**هذه نسخة تجريبية ببيانات وهمية، وليست نظامًا معتمدًا للاستخدام مع الطلاب الحقيقيين.** لم يُفعَّل ربط الجامعة أو تسجيل Google أو التحقق المؤسسي أو الذكاء الاصطناعي. لا ترفع مستندات شخصية حقيقية في وضع التجربة.

## التشغيل السريع

المتطلبات: Node.js 24 أو أحدث، وnpm، وChromium لتوليد الاستمارة. الخطوط العربية محلية ولا يتطلب تشغيل الواجهة اتصالًا بخدمات خطوط خارجية.

```bash
cd /workspace/SCU_Website
npm ci --cache /tmp/scu-npm-cache
DEMO_MODE=true npm run dev
```

واجهة التطوير على المنفذ `5173`، والخادم على `3001`. يمر الوصول إلى `/api` عبر وكيل Vite. لا تُنشئ worktree؛ استخدم نسخة المشروع الموجودة داخل بيئة المهمة المعزولة.

تعرض شاشة الدخول خيارات تعبئة بيانات الحسابات التجريبية:

| الحساب | البريد | كلمة المرور | الصلاحية |
| --- | --- | --- | --- |
| الطالب | `student@demo.local` | `Demo2026!` | تقديم نشاطه ومتابعته |
| الموظف | `moderator@demo.local` | `Demo2026!` | مراجعة الطلبات والاعتماد |
| المسؤول الرئيسي | `admin@demo.local` | `Demo2026!` | المراجعة وإدارة الموظفين |

هذه كلمات مرور معلنة لحسابات تجريبية فقط. لا يمكن إعادة استخدام قاعدة البيانات التجريبية عند إلغاء `DEMO_MODE`؛ استخدم مجلد بيانات جديدًا تمامًا عند تجهيز بيئة غير تجريبية.

## تشغيل النسخة المبنية

```bash
npm run build
DEMO_MODE=true COOKIE_SECURE=false npm start
```

يقدم الخادم التطبيق والـAPI من المنفذ `3001` في هذه الحالة. `COOKIE_SECURE=false` مناسب للتجربة المحلية عبر HTTP فقط، وليس للنشر الحقيقي. للتحقق داخليًا:

```bash
curl --fail http://127.0.0.1:3001/api/health
```

## الوظائف المتاحة

- حساب الطالب وبياناته المرتبطة به، ومسودة واحدة لكل طالب في الفترة المحددة.
- تسجيل اسم النشاط ونوعه وجهته وتاريخه ووصف المشاركة.
- رفع حتى ٥ مستندات: PDF وPNG وJPEG، بحد أقصى ٨ ميجابايت للملف، مع فحص توقيع الملف وصلاحية الوصول.
- تقديم الطلب وإيقاف تعديله أثناء المراجعة؛ التعديل يُعاد تفعيله عند طلب الاستكمال.
- إنشاء PDF عربي قابل للطباعة من لقطة محفوظة عند التقديم؛ تُحفظ إصدارات الاستمارة عند إعادة التقديم.
- البحث بالاسم أو الرقم الجامعي أو الرقم القومي أو اسم النشاط، والتصفية بالحالة وترقيم الصفحات. لا تظهر أرقام قومية في نتائج البحث.
- الاعتماد بعد تأكيد استلام الاستمارة الورقية ومطابقتها؛ إعادة للاستكمال، وعدم اعتماد، وإلغاء.
- احتساب ٤٠ درجة فقط عندما تكون الحالة `approved`، دون درجات جزئية أو إضافة متكررة.
- سحب الاعتماد وإعادة فتح الطلبات بواسطة المسؤول الرئيسي فقط، مع تسجيل السبب.
- إضافة موظفين بصلاحية مراجعة، وتعطيل حساباتهم وإنهاء جلساتهم.
- سجل مراجعات، وصلاحيات على الخادم، وجلسات عبر cookies من نوع HttpOnly، وحماية CSRF، وتحديد محاولات تسجيل الدخول.
- واجهات عربية من اليمين إلى اليسار، مناسبة للكمبيوتر والموبايل، مع حالات تحميل وأخطاء ونتائج فارغة.

## الاختبارات

```bash
npm test
npm run build
npm run test:browser
```

`npm test` يختبر دورة العمل والصلاحيات والخصوصية والاستمارة وإلغاء الجلسات باستخدام قاعدة بيانات مؤقتة منفصلة. اختبار المتصفح يحتاج بناء الواجهة أولًا وChromium؛ يشغّل نسخة مستقلة ببيانات مؤقتة، ويجرب التقديم والاستكمال والاعتماد وتنزيل PDF وإدارة الموظفين والموبايل.

تُكتب نتائج المتصفح ولقطات الشاشة في مجلد جديد داخل `test-results/` لكل تشغيل، وهو مستبعد من Git. لا تُستخدم بيانات `.data/` في الاختبارات.

## بنية المشروع

```text
config/faculty.json   هوية الكلية وإعدادات الفترة ومكتب التسليم
src/                 واجهات React وTypeScript
server/              Express وSQLite والجلسات وتوليد PDF
tests/               اختبارات الخادم والمتصفح
public/fonts/        الخطوط العربية وترخيصها
.data/               قاعدة البيانات والمرفقات والاستمارات؛ غير مرفوعة إلى Git
```

تُحفظ البيانات فعليًا في SQLite، والمرفقات في مجلد خاص خارج ملفات الواجهة العامة. لا يوجد اعتماد على التخزين المحلي للمتصفح لحفظ الطلبات.

## الإعدادات

تُمرر المتغيرات إلى العملية؛ ملف `.env.example` توثيقي، ولا يُقرأ ملف `.env` تلقائيًا بواسطة الخادم.

| المتغير | الاستخدام |
| --- | --- |
| `DEMO_MODE` | `true` لإنشاء حسابات وبيانات تجريبية في مجلد فارغ |
| `DATA_DIR` | مجلد قاعدة البيانات والمرفقات والاستمارات؛ الافتراضي `.data/` |
| `PORT` | منفذ الخادم؛ الافتراضي `3001` |
| `CHROMIUM_PATH` | مسار Chromium؛ الافتراضي `/usr/bin/chromium` |
| `APP_ORIGIN` | أصل الموقع الرسمي عند اختلافه عن عنوان الخادم خلف الوكيل |
| `COOKIE_SECURE` | `true` لإرسال جلسات الدخول عبر HTTPS فقط |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | تهيئة أول مسؤول في قاعدة غير تجريبية فارغة؛ ١٢ حرفًا على الأقل لكلمة المرور، وتُمرر عبر إعدادات آمنة |

عدم تفعيل الوضع التجريبي لا يفعّل Google أو ربط الجامعة تلقائيًا. لا يوجد تسجيل عام للطلاب؛ يلزم تنفيذ التكامل المعتمد أو استيراد سجلات الطلاب وآلية تحقق قبل استخدام بيانات حقيقية.

## قبل التشغيل الرسمي

تحتاج الجهة المختصة إلى تحديد نموذج الاستمارة، وقواعد الأنشطة والمستندات، والفترة الدراسية، ومكتب التسليم، والهوية الرسمية، والموظفين، وطريقة توثيق الطلاب. كما يلزم ربط الجامعة وتحديد الاستضافة وHTTPS وسياسة البيانات، واسترداد الحسابات، وتشغيل نسخ احتياطية مجدولة واختبار استعادتها، واختبارات حمل وأمان مناسبة للحجم الفعلي.

لا توجد مزامنة مع خادم الجامعة ولا نسخ احتياطية مجدولة أو خدمة مساعد ذكي في هذه النسخة. البيانات والمؤشرات المعروضة في وضع التجربة مشتقة من السجلات التجريبية، ولا تمثل أعدادًا رسمية.

للتخصيص لكل كلية، ابدأ بنسخة المشروع المستقرة، وعدّل `config/faculty.json` والهوية البصرية، واستخدم مجلد بيانات وإعدادات مستقلة. الربط المركزي لاحقًا يحتاج واجهة معتمدة وعزل الصلاحيات ومعالجة انقطاع الاتصال؛ نسخ الفولدر وحده لا ينفذه.
